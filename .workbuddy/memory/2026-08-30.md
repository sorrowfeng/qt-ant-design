**git 对象库损坏恢复（重要教训）**：
- 起因：`git stash` 在特殊状态下报 `fatal: ... is not a valid object`，导致 HEAD(d9f9d47) 指向的 tree 658ff7981 丢失、`git status` 报 `error: bad tree object HEAD`、`git fsck` 报 broken link/missing object。
- 关键诊断：`git fetch origin dev --force` 无法恢复，因为 fetch 需读取本地已缺失的父提交 866c0ac。
- 最终方案：`git clone --branch dev --single-branch` 到 /tmp 验证远程对象完整（fsck 无错）→ 备份本地 4 个改动文件 → 复制到干净 clone → commit(4429b9a) → push → 用干净 `.git` 替换本地损坏 `.git`（`mv .git /tmp/broken-git-backup && cp -r clone/.git .git`）。
- 恢复后工作区 124 个文件显示 CRLF/LF 差异（`* text=auto` + `*.cpp text eol=lf` 规则，Windows 检出 CRLF），用 `git add --renormalize .` 一次性规范化；3 个 binary svg 残留用 `git checkout --` 恢复，最终 `working tree clean`。
- 教训：**不要在对象库异常时用 `git stash`**；本地对象损坏且远程引用一致时，最可靠是重新 clone + 替换 `.git`，而非反复 fetch/fsck 修复。

## CI 修复补充（提交 40424de）

第一次 CI 修复（8db428d）后，Windows Qt5 job 又暴露一个新失败：TestAntDeepCoverage 的 ribbonPageAndGroupManagement 在 Qt5 下 `actionTriggered(QAction*)` 信号参数无法被 QSignalSpy 捕获（QAction* 未注册 metatype），断言指针不匹配。

根因：Qt5 下 QAction* 不会自动注册 metatype（Qt6 通过 QMetaType 自动处理）。修复：在 AntTypes.cpp 的 registerMetaTypes() 中补 `qRegisterMetaType<QAction*>("QAction*")`，同时修复潜在跨线程 queued connection 失效。

关键教训：
- 用 QAction*（或任意 Qt 指针类型）作信号参数时，Qt5 下需显式 qRegisterMetaType，否则 QSignalSpy 与 queued connection 都会失效。
- 本地复现 Qt5 问题需独立 build 目录：`cmake -B build-qt5 -DCMAKE_PREFIX_PATH=C:/Qt/5.15.2/msvc2019_64`，运行测试 exe 需 PATH 加 Qt5 bin 目录。
